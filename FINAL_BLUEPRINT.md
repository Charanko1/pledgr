# PLEDGR Final Blueprint\n\n## Roles\n- Member: creates proposals and participates in normal group activities.\n- Validator: group-scoped role assigned by an Admin; reviews proposals and withdrawal requests.\n- Admin: manages group membership/validators and gives final proposal/withdrawal approvals.\n\n## Proposal lifecycle\n1. Member creates a proposal -> `Pending`.\n2. Validator approve/reject -> `Validated` or `Rejected`.\n3. Admin approve/reject -> `Approved` or `Rejected`.\n4. Creator registers the approved proposal on-chain.\n5. Contract admin activates funding on-chain -> `Funding`.\n6. Donors send native BOT to the PLEDGR treasury contract.\n7. When the target is reached or the deadline passes, the creator requests withdrawal.\n8. Validator approves/rejects the withdrawal.\n9. Admin gives the final release approval or rejects it.\n10. Contract admin calls `releaseFund()` -> BOT goes to the creator wallet.\n\n## Delete vs Cancel\n- Delete: creator only, while the proposal is `Pending` and has never been registered on-chain.\n- Cancel: creator or group Admin after the proposal has entered a persisted/on-chain workflow, except after funds are released. Cancellation closes new donations and lets each donor claim their own refund.\n- A rejected withdrawal is not a refund. The BOT remains in the contract and the fundraiser may request withdrawal again.\n\n## Blockchain\nRemix is the compile/deploy workflow. The app uses Ethers.js. BOT is the native currency of the configured BOT Chain testnet. MongoDB stores metadata and verified transaction history; the blockchain is authoritative for token balances and transaction execution.\n\n## Realtime\n- Application state: focused React Query polling keeps join requests, memberships and proposal views fresh without refresh.\n- Blockchain state: Ethers contract event listeners react to on-chain events (`CampaignCreated`, `CampaignApproved`, `Donated`, `CampaignCancelled`, `RefundClaimed`, `FundReleased`).\n
